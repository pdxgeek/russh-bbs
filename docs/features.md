# Feature register

Status values: **Planned**, **In progress**, **Implemented** (code exists), **Verified** (tests and a real `ssh` run). Rows say what is true now: M0 and M1 rows are Implemented or Verified, M2 and later rows are Planned.

Update this table in the same pass as the code.

| Feature | Milestone | Status | Notes |
|---|---|---|---|
| QA pass per milestone (`docs/qa/`) | all | Planned | Gate before the next milestone starts |
| Workspace, CI, threat model | M0 | Implemented | Workspace, toolchain, deny and CI exist and pass locally (fmt, clippy, test, deny); CI runs on GitHub for every PR (check and deny jobs). Threat model is a doc. Not yet Verified |
| Shared sanitizer | M0 | Implemented | `russh-bbs-core::sanitize`: controls, ANSI/CSI/OSC/DCS/APC/PM/SOS and 8-bit C1 sequences, bidi, invisible filler and format characters, Unicode-space mapping, combining-mark cap, private-use and reserved-chrome neutralization, char-count limits, `Sanitized` newtype, NFKC + strict ASCII usernames, reserved usernames compared ignoring separators with extra leet folds and staff words (D45), ASCII lookalike skeleton with digit and pair folds (D40, FIX-M0-1). Invisible/format characters are stripped by Unicode property (`Cf`, Default_Ignorable; D45) and the combining-mark cap survives ZWJ/ZWNJ. Lookalike brackets and glyphs of the markers are not blocked (D45). Unit and property tests; no fuzz target yet (Planned). Not yet used by any front end. Not yet Verified |
| Icon registry and width table | M0 | Implemented | `russh-bbs-core::icons`: closed enums (`ContentIcon`, `SecurityMarker`, `Icon`), three tiers, text labels, explicit width table, padded `render`. Reserved presentation per tier (style, `⟦ ⟧` delimiters for the exact codepoints only, ASCII limit and lookalike limit stated honestly, D39, D45); `ContentIcon::Restricted`. Unit and property tested incl. sanitizer round-trip. Used by the M1-E glyph test only yet. Multi-terminal alignment **not verified** (needs real terminals). Not yet Verified |
| SSH server, host key, public-key auth | M1 | Verified | M1-A (`russh-bbs-server::ssh`, `russh-bbs-core::access`). Persistent Ed25519 host key (0600, outside the repo, stable fingerprint logged at start); public-key-only auth; every unknown key gets a restricted session showing a placeholder screen (the real waiting room is M1-C). Lockdown: exec, subsystem/sftp, env, agent, X11, direct-tcpip, tcpip-forward and streamlocal all refused. PTY size honored, clamped, and updated on resize; auth timeout, auth-attempt cap, idle timeout and connection cap. 23 unit + 31 integration tests (real russh client on loopback) and a manual run with OpenSSH `ssh`/`sftp` (see PR). **Not covered:** RSA client keys (unsupported by design, D21), clients other than OpenSSH and russh, load or fuzz testing of the transport (QA M1 found flood problems, see FIX-M1-1). Per-IP and per-key limits are the M1-C row. Members and the founder (`Access::Member`) are tested end to end over SSH (`tests/ssh_store.rs`, `tests/founder.rs`) |
| Waiting room (banner, rules, request, redeem), mode-aware | M1 | Implemented | M1-C, `m1/waiting-room`. Screen set follows `registration_mode` (invite: request + redeem; apply: application; open: create account), rules in core, drawn by the SSH front end. Banner and rules are sysop settings, sanitized. Forms take sanitized, length-capped input and then say plainly that the feature is not open yet and nothing was stored or sent: the real invite, apply and create-account flows are M2. Tested in all three modes, including no-leak tests and a real russh client; walked with OpenSSH. D37 |
| Per-IP and per-key rate limits | M1 | Implemented | M1-C. GCRA limiter in core with a fake clock; per network at accept, per key at auth, per-session form cap; bounded memory with eviction. In-memory (resets on restart). D37 **Per-session bounds after login (FIX-M1-1, D49):** window changes coalesced and redraws capped at 20 a second, request and input byte budgets with a strike limit that disconnects a flooding session, a bounded output queue with a socket-level cut-off for a peer that stops reading, five operator keys under `[ssh]`. Tested with unit tests (budgets with a fake clock, one redraw per batch) and real russh clients (`tests/ssh_flood.rs`); before/after CPU and memory numbers are in the PR. **Per-session render cost (FIX-M1-3, D52; FIX-M1-4, D53):** a session draws into at most `ssh.render_cols` x `ssh.render_rows` cells (default 500x200, the whole clamped window; a bigger window is centered on the cap), `ssh.max_connections` defaults to 64, and the server logs the resulting memory ceiling at start; buffers are resized in place on a window change. Tested with unit tests (cap applied, default draws the whole window, in-place resize keeps the allocation) and real russh clients (`tests/ssh_session.rs`: capped and default layouts). **Not covered:** many sessions each at budget, allocator memory retention after a flood, a re-measurement of memory at the new default (the bound is arithmetic: 64 x 9.6 MB). |
| Founder / first-run sysop claim | M1 | Implemented | `m1/founder` (D41). One-time 160-bit setup token printed to the console at start (in-memory hash, a restart re-issues); `ssh claim@host` opens a prompt that is identical claimed or not; atomic compare-and-set claim creates an active `sysop`-role account; per-key and per-network limits; sessions then see a "signed in" placeholder. Tested on SQLite incl. a race, over a real russh client and OpenSSH (restart persistence). Not verified: Postgres (M1-G), timing side channels beyond the constant-time compare. Roles/permissions are M2's |
| Per-user terminal settings | M1 | Implemented | `m1/terminal-settings` (D42). Per-account width and height overrides, color, pause and icon tier in `terminal_settings` (migration `0002`); `core::terminal_settings` rules; settings screen reachable from the signed-in home. **Glyph test** on first login (registry glyphs per tier, y/n/Esc), re-runnable from settings; skipped or answered no stores ASCII with color off, and ASCII with no color is also what is drawn until it is answered. Tested in core (rules, flow), the store (through the core traits) and over a real russh client, and walked with OpenSSH under `pyte` and `tmux`. **Pause is stored but changes no output** (nothing pages yet); glyph alignment in real Nerd Font terminals not checked |
| Login and logoff screens, themeable strings | M1 | Verified | `m1/terminal-settings` (D42). Login screen ("Signed in as <handle>", last login in UTC, the stored tier, color and pause), glyph test when needed, placeholder home, logoff screen also left in the scrollback. Every fixed string is in `core::terminal_settings::strings`; the handle goes through the sanitizer. Exercised with OpenSSH (claim, reconnect, glyph test, reconnect without it, resize, logoff). Themes that replace the strings are M3 |
| SQLite store and migrations | M1 | Implemented | `m1/store`, restructured in `m1/postgres` (D44): code in `crates/store/src/sqlite`, migrations in `migrations/sqlite/` (content unchanged, checksums pinned; a database made before the move opens and keeps its data - tested). `sqlx` (D34), WAL, forward-only checksummed migrations (D36), accounts, key fingerprints, settings; `MemberDirectory` over the store (active accounts only, fails closed). Tested on temp-file DBs and with OpenSSH. Account/state transitions beyond create, and the founder flow, are M1-D/M2 |
| Postgres backend | M1 | Implemented (PGlite not working) | `m1/postgres` (D44, D24, D31). `PostgresStore` over `sqlx` with Postgres-native SQL and its own migrations (`migrations/postgres/`); every core store trait including the atomic founder claim and terminal settings; TLS always on (`require`, `verify-ca`, `verify-full`, root cert), password never in errors or logs. **The same shared suite passes on SQLite, on a Postgres 16 service and on a Postgres that requires TLS** (CI job `postgres` and `postgres-tls`; also run locally on Postgres 16, TLS 1.3). **PGlite via `pglite-socket` does not work** with a pooled sqlx client (single shared session: prepared-statement name collisions); D6 asked for it, so this is open for the owner. Managed Postgres (RDS) is this backend plus TLS (D31) and was not tried against a real RDS. IAM token auth is parsed and refused at boot |
| Datasource selection in config | M1 | Implemented (IAM auth refused) | `datasource.kind` = `sqlite` (`path`) or `postgres` (`url`, `tls_mode`, `tls_root_cert`); selected at boot in `main.rs`, with no fallback from one to the other. `iam_auth = true` is **parsed and refused at boot** with its own error (D31, D44). A bad URL, an unreachable server, a TLS failure or a refused login stop the boot with a message that never contains the password. Tested in the config unit tests and the store tests, and exercised with the real binary and OpenSSH on SQLite and on a TLS-required Postgres (claim, reconnect, second claim refused). Never MySQL |
| Container image, compose example, GHCR publish | M1 | Implemented (image); **publish untested** | M1-F (D25, D43), FIX-M1-2 (D46). `Dockerfile` (static musl, `scratch`, UID 65532, all state in `/data`; bakes only `RUSSH_BBS_LISTEN`, so `/data` is the default data directory and Postgres works), `compose.yaml`, `docs/deploy.md`, tag-only multi-arch GHCR workflow with a no-push `workflow_dispatch` dry run, PR jobs (amd64 build + SQLite and Postgres smoke; amd64+arm64 build without push). SIGTERM/SIGINT graceful shutdown, tested against the real binary. Verified locally with real Docker and OpenSSH (amd64, musl binary built on the host because the in-Docker build fails behind this environment's TLS proxy): empty volume, DB and host key under `/data`, token in `docker logs`, waiting room and `claim@`, restart keeps fingerprint (checked with strict host-key checking) and sysop, `docker stop` exits 0 in about 0.3 s; `RUSSH_BBS_DATASOURCE_KIND=postgres` reaches the listening state against a TLS-only Postgres in `require` and `verify-full` with `tls_root_cert` on the volume, no password in logs. Not verified: the `Dockerfile` builder stage (not run here: TLS proxy), the arm64 image, the GHCR publish (runs only on a tag, which is the owner's action), the GitHub workflows until their CI run is recorded in the PR, bind-mount permissions |
