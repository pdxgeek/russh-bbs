# QA report: M3 Public core

Reviewer: QA session (did not write the code; no code changed, only this file, M3 status text in `docs/features.md`, and rows in `docs/coordination.md`). Date: 2026-11-03.
Tested: `main` at **`48494ad`** (merge of PR #69; M3-A to M3-J, FIX-M3-1 are in). Scope: M3 "Done when" in `docs/milestones.md` and the QA-gate brief.

## Verdict

**M3 passes the gate.** The three "Done when" clauses hold over real clients against the container image built from `main`, from an empty volume: three members (alice, bob, carol) posted, replied with a quote, searched, chatted (presence, a whisper) and exchanged mail over plain OpenSSH 9.6; a malicious feed (escape codes, C1, bidi, private-use, marker codepoints, SSRF redirects, bombs, oversize, slow drip) was neutralized by the tests **and** live through the running server; the layout and theme switch live. I found **no high finding**: nothing leaked to an unknown key, no hostile text reached the screen, the log or the database as a control or marker character, mail was never readable at rest, and every limit I flooded held.

Three **medium** findings and several low ones are below. As in M2, the next milestone should not start until the medium rows (FIX-M3-3 to FIX-M3-5) are Done or the owner accepts them.

| ID | Severity | One line |
|---|---|---|

## Environment and recipe

Linux container, OpenSSH 9.6, `telnet`, `nc`, `sqlite3`, `tmux` (each client ran in its own tmux pane at 80x24 and I read the screen with `capture-pane`, with `-e` for styles), Docker 29 (daemon started with `dockerd`). Postgres 16 server binaries from the image, started by me on ports 5433 (TLS required, `.github/scripts/postgres-tls-server.sh`) and 5434 (plain). All Docker names start `russh-bbs-qa-`; I removed nothing else. Keys were generated at test time and are not committed.

```bash
git rev-parse --short HEAD                      # 48494ad
rustup target add x86_64-unknown-linux-musl; apt-get install -y musl-tools
SQLX_OFFLINE=true cargo build --release --locked -p russh-bbs-server --target x86_64-unknown-linux-musl   # 2m35s
```

**Deviation:** `docker build --build-arg BIN_STAGE=prebuilt ...` (docs/deploy.md) failed because Docker Hub answered `429 Too Many Requests` for `alpine:3`. I built the same image from a QA-only Dockerfile outside the repo: `FROM scratch`, the same binary, `COPY --chown=65532:65532 data /data` (mode 0700), `USER 65532:65532`, `VOLUME /data`, same entrypoint and `RUSSH_BBS_LISTEN`/`RUST_LOG` env. `docker inspect` showed user 65532:65532 and no `-t`. The repo `Dockerfile` itself was not exercised end to end.

For the walk I set `RUSSH_BBS_IP_BURST=1000 RUSSH_BBS_KEY_BURST=1000` (all clients share the Docker bridge address); defaults were left alone otherwise. The feed run used a **second** binary built with `--features qa-loopback-feeds` (the slice's own switch for exactly this; it is not in the release build, and `QA_FEED_ALLOW` names one `ip:port`), image `russh-bbs-qa-img-feed`, against a hostile feed server I wrote (`172.17.0.1:9099`).

## Findings

### M1. Telnet shows a new invite code in clear (Medium)

D85 (2) removed the waiting room, claim and invite redemption over telnet "because each would put a key, an invite code or a setup token on the wire". But `Invites` is still in the telnet menu, and creating an invite shows the one-time code.

Reproduce: telnet on and `allow_login` on, a member with a password signs in over `telnet`, `i`, `c`. The screen shows `Invite code: GTKP-KHC4-...` (also true of the demoted sysop, within the member quota). Anyone on the path can read and redeem it first. Expected: withhold invite creation over telnet like mail ("Invites are available over ssh."). Fix: FIX-M3-3.

### M2. Board list does not scroll (Medium)

Reproduce: as the sysop add 20 boards (feeds do this fast). The list draws 18 rows; `Down` keeps moving the cursor past the drawn rows (the highlight disappears) and `Enter` opens a board that is not on screen (`F-cookie` opened blind); `1`-`9` only reaches the first nine. The notice line "Feed added" is also pushed off the screen by a long list. No data is lost (search still finds posts), but boards past the screen are effectively unreachable and nothing says so. Fix: FIX-M3-4 (scroll or page the list; keep the notice visible). **Fixed on `fix/m3-board-list`:** the board list, the thread list and search results scroll with the cursor, a position line (`7-21 of 25`) shows when not everything fits, the notice and selected row are always drawn (the help line and the heading's extra lines give way on a very small screen), and digits count the drawn rows.

### M3. No CA store in the image, https feeds cannot load (Medium)

Start: `feeds.enabled=true` in the image. The log says `no CA certificates found: https feeds cannot be verified and will not load`. Since plain http needs a per-feed flag and is discouraged, the feed feature cannot be used in the documented container. `deploy.md` explains the missing CA store for Postgres only. Fix: FIX-M3-5 (document it and offer a way, for example a `feeds.tls_root_cert` file on the volume like Postgres, or a CA bundle in the image, an owner decision).

### Low findings

- **L1.** `ssh/screen.rs` `set_low_security` is applied to the invite-request queue only. The `Sysop tools` menu and the staff keys in forums, chat and community show only `SERVER-READABLE`. Already noted in the M3-H hand-off for M5; re-checked: still true.
- **L2.** The Terminal settings, Password, icon-check and "Signed in" screens draw no status row (`settings::render` is the unframed path). Known and documented (D39 note, M3-D "Not verified"); on those screens the marker is absent even though they sit inside a server-readable session. Telnet's transport row still shows.
- **L3.** `café 日本 😀` pasted into a one-liner became `caf` (key parser delivers ASCII only, `ui.md`). Documented, but members get no hint.
- **L4.** Pasting `first line\nsecond line` into a single-line input gives `first linesecond line`. A space would be kinder.
- **L5.** `Ctrl-C` saves a draft; killing the connection mid-edit (tmux kill) loses the text.
- **L6.** Report confirmation wraps `fr|om` mid-word; "1 votes in all."; the chat room page shows a bare "You are in" line; settings says "Pause at screen end: on (applies to long text; no screen pages yet)" although the reader pages.
- **L7.** The welcome and help screens over telnet repeat "No one, the sysop included, can read your mail through the board" on a connection marked `UNENCRYPTED`, where mail is withheld. Consider omitting the sentence for telnet.
- **L8.** `docs/features.md` lines for "Internal mail" and "RSS in" still have a `Planned` twin row; the editor row says no screen calls it; the scheduler row says no jobs are registered (`feeds-poll` is). Docs only.
- **L9.** With `ssh.allow_password_login` on, an interactive `ssh` told only `Permission denied (publickey)` after one wrong password (default client allows three prompts). Fewer retries than OpenSSH sshd; confirm intent.

### Notes, not findings

- Typed OSC text leaves visible `0;PWNED`: the key parser eats the introducer and the rest is ordinary printable text. Harmless.
- Server logs the full config at start (`configuration loaded`); no secret in it (the Postgres URL is masked by design). The log never contained a canary, password or invite code.
- Member `calls_per_day` is 5, so repeated QA sign-ins exhaust accounts quickly; as designed.
- A `poll` shows who voted to the sysop only; the screen never claims secrecy.
