Reviewer: QA session (did not write the code; no product code changed, only this file, `docs/qa/m4-screens/` and rows in `docs/coordination.md`). Date: 2026-11-06.
Tested: `main` at **`ea0ee90`** (DOC-1 on top of FW-1 `970ef2a`, which is on top of H4 `5b7a85c`). The first pass ran on `5b7a85c`, before FW-1 and DOC-1 merged; I merged main, rebuilt, and **repeated the door sweep, the two-account walks, the monkey runs and the security spot checks on `ea0ee90`** with the same results. Merged and in scope: M4-D0 door framework (D98, D104) with FW-1 (world read, render-time clock, world replay, look-around key), M4-F1 BlobStore (D106), Saltmarch S1 to S4, Emberdeep E1 to E3, Nullroute N1 to N3, Long Haul L1 to L3, Hallpass H1 to H4. **Not merged, so not tested (phase 2): F2 SFTP, F3 new-scan, S5, E4, N4, L4, H5.**

## Verdict

**Phase 1 of 2: no high finding and no medium finding; two low findings and a list of balance flags. The M4 gate is not closed** (half the milestone is still in progress, and the balance and social slices that are left are the ones the flags below land on).

What held, with the numbers:

- **The reserved style appeared only on the marker cell, in every combination I walked.** 7 layouts x 9 styles = 63 combinations, each opening Coin Toss and the five games, in the Nerd Font, Unicode and ASCII tiers, over ssh and over a raw telnet client: **6 sweeps, 378 combination runs, 2,268 door visits, 0 violations**. Counted on the raw bytes (every cell drawn or erased while reverse video was on): a telnet member got bold+reverse on **row 23, columns 0 to 10 only** (`UNENCRYPTED`, 11 cells) through all six doors; a staff ssh session on a board with telnet on got it on **row 23, column 0 only** (the marker glyph, 1 cell); an ordinary ssh member got **no reverse cell at all**. Plain (non-bold) reverse video: **0 cells** in 2,268 door visits (the door selection bar M3.5 found in reverse video, L1 in [m35.md](m35.md), is gone: D130).
- **The marker survived every door key.** 2,500 random keys across the five games on staff ssh sessions and telnet members: the first 16 cells of the status row were unchanged and cell 0 stayed bold+reverse on every key (**0 mismatches**). M3.5's M1 (marker missing on every running door) is fixed.
- **Hostile text is contained.** The clan-name field takes ASCII only; a name with lookalike marker, `〚 〛`, RLO, ZWSP, Nerd PUA, BEL and C1 CSI was cut to its ASCII residue and refused as "not allowed here"; the same string in a letter line reached the recipient as `hi []31m done` with **0 BEL, 0 C2 9B, 0 RLO, 0 ZWSP, 0 PUA, 0 U+301A** in the recipient's raw bytes.
- **Saves and world:** the shared Saltmarch world and both clans survived two restarts under `faketime` (with a trade, a letter and a raid posted across them); a `SIGKILL` of the server with a door open lost nothing already saved; a server down for 8, 60 and 70 days came back with a capped catch-up and no crash; two sessions of one account did not clobber each other (the second was closed with a clear message).
- **Social caps held where I could see them:** the unread-per-sender cap held (2 unread out of 17 tries), the new-clan week and the pair cooldown showed on the gate, the opted-out Hallpass pupil could not be targeted and the opt-out text said so.

## Environment and recipe

Linux container, 4 cores, OpenSSH 9.6 (`apt-get install openssh-client`, it is not in the image), `telnet` 0.17 and my own raw telnet client (`telnetc.py`, answers NAWS and terminal type, no local echo), `tmux`, Python 3.13 with `pyte`, `faketime`, `cargo-deny` 0.20.2 built with `cargo install`. No Docker (the server binary is the object under test). All clients ran in tmux panes (ssh `-tt`) or a pty (the authors' walks); raw bytes were tapped with `pipe-pane` and counted with the M3.5 `Tally` screen. The tools are in [m4-screens/tools/](m4-screens/tools/README.md); keys and passwords were made at test time and are not in the repo.

```bash
git merge origin/main                                             # ea0ee90
SQLX_OFFLINE=true cargo build --release --locked -p russh-bbs-server   # 1m38s incremental
tools/bstart.sh DIR PORT TPORT [faketime -f +60d]                 # scratch board per walk, telnet on
python3 tools/doorsweep.py ssh|telnet PORT USER 80x24 nerd|unicode|ascii OUT   # six in parallel, about 25 minutes
```

Things that cost me time and are worth knowing: (1) the debug `target/` of this workspace grew to **28 GB** and filled the container's disk allowance during the first `cargo test --workspace`, which broke that run and some scripted account creation (`No space left on device`); I deleted `target/debug` and ran the final checks with `CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0`. (2) `open` registration allows five new accounts per network per run (per-network rate, D74), so a scripted multi-account walk needs a server restart after five joins. (3) The S4 author's `walk.py` needs the cloud container's `faketime` and OpenSSH, as the H2 handoff said.

### L1 (Low): Saltmarch drops letters over the unread cap without telling the sender

- **Repro.** Two accounts on a board. Account A: Tidecourt, The post, `Write a letter`, `Send the letter to`, eight times in a row, then again eight times. Then open the recipient's post, and reopen A's door for the next morning's report (I restarted the server under `faketime +62d` for that).
- **Expected.** A sender whose letter is refused (*That clan already has letters from you it has not read.*, `Refusal::Unread`) is told, at the latest in the next report, as the exchange and raid answers are.
- **Got.** Every send said *Your letter goes to founder.* The recipient's post held 2 unread from A. A's report after the gap read *14 nights passed ... Letters: 1 waiting at the post* and listed no refusal. I did not trace the settlement code: the dispatch may be answered somewhere I did not look (a screen other than the report and the post). If it is, the fix is only a pointer on the sender's screen; if not, the sender has no way to learn that a letter was lost. Either way the claim "goes to" is stronger than what the rules promise.
- **Proposed owner.** The S5 slice (Saltmarch social is S4's, merged; S5 is open).

### L2 (Low): Hallpass after a long absence

- **Repro.** An enrolled pupil who played on day 12; restart the server under `faketime +70d`; open Hallpass as that account.
- **Expected.** The first screen says the term ended and what happened, or the finished term is somewhere the player can find it.
- **Got.** The enrolment card (*Who do you want to be known as?*), then, after choosing, *term 2, day 7 of 42* with legend 0 and cash 12. The footer keys offered no hall or yearbook (`y` did nothing visible). The design rolls the term over in the daily tick, so a new card is right; what I could not find is where the old term's ending is recorded. Not verified further.
- **Proposed owner.** H5.
